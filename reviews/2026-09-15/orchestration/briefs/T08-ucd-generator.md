## T08 — PLAN 1.2: deterministic Unicode property table generator

Claim the beads issue for plan item 1.2. Ground truth is the vendored data under `reference/unicode/17.0.0/`, which T07 added. Verify it exists, and check its `SHA256SUMS` before you start.

### What to build

1. **A generator script.** Write it as `scripts/gen-unicode-tables.clj`, runnable as `bb gen-unicode`.
   - It reads the vendored UCD files and writes `src/limner/unicode/tables.clj`.
   - That output is a namespace with an AUTOGENERATED banner. The banner names the Unicode version, the source file paths, and their SHA-256s (read from `SHA256SUMS`), and says "do not edit; run `bb gen-unicode`".
   - The generator is deterministic and byte-stable: sorted output, no timestamps, stable formatting.

2. **The tables.** For each property, emit compact, merged, sorted ranges as `[start end value]` triples. Use a flat primitive encoding if that loads faster; measure both on bb before choosing. The later tasks need these properties:
   - `East_Asian_Width` (all classes; the unlisted default is N, per the file's header).
   - `Grapheme_Cluster_Break` (all values; the default is Other).
   - `Extended_Pictographic` (from `emoji-data.txt`).
   - `Emoji_Presentation` (from `emoji-data.txt`).
   - `Default_Ignorable_Code_Point` (from `DerivedCoreProperties.txt`).
   - `InCB` (`Indic_Conjunct_Break`: Linker / Consonant / Extend, from `DerivedCoreProperties.txt`; confirm where T07 found it).
   - `General_Category` (from `extracted/DerivedGeneralCategory.txt`). Emit either all categories, or only the subset the width rules need (Mn, Me, Mc, Cf, Cc, Zl, Zp, Cs, Co, Cn). Justify the choice in the namespace docstring. Smaller is better if later tasks only need the subset: look at PLAN D3 and the width semantics to decide.
   - Handle `@missing` default lines correctly. The 17.0 files use `# @missing:` lines to declare defaults, and they matter (for example the EAW default for unassigned CJK ranges is W, not N). Parse them and apply them as the file header specifies. Get this right against the file itself, not memory.

3. **A lookup namespace, `limner.unicode`.** Public functions:
   - `version` returns `"17.0.0"`.
   - Property lookups by code point: `east-asian-width`, `grapheme-break`, `extended-pictographic?`, `emoji-presentation?`, `default-ignorable?`, `incb`, `general-category`.
   - Lookups use binary search over the ranges and must run in constant memory.
   - Lookups throw `ex-info` for inputs outside 0..0x10FFFF. That is fail-loud behaviour (Rule 1).
   - Write a literate namespace docstring (Rule 10) covering what the data is, which version it comes from, how defaults work, and why the tables are generated.

   Do not implement width or segmentation rules here. Those are 1.3 and 1.4.

### Tests

Write these red first.

- **Drift test.** Regenerate into memory or a temp file and compare byte-for-byte with the committed `tables.clj`. It fails if someone edits the tables by hand or changes the UCD files without regenerating. It must run on both runtimes.
- **Spot tests against the raw data.** For a few hundred code points sampled deterministically (fixed seed) across all planes, parse the raw UCD line for that code point directly in the test (an independent simple parser, not the generator's code path) and compare it with the lookup. Include the edge cases:
  - `@missing` defaults
  - U+10FFFF
  - surrogates
  - private use
  - unassigned code points in the CJK blocks
- **Exact checks** for a few property values we already know from REVIEW C1/C2:
  - EAW: U+3000 W, U+2630 W, U+2713 N, U+1F170 A.
  - Emoji_Presentation: U+26A1 true, U+2764 false.
  - Default_Ignorable: U+00AD true, U+FEFF true.
  - GCB: U+200D ZWJ, U+1F1E6 Regional_Indicator.
  - One InCB Linker, for example U+094D.
- **Mutation-prove.** Edit one generated range by hand, confirm the drift test and at least one spot test go red, then restore.

### Performance

Report the following on both JVM and bb:

- namespace load time
- lookup throughput (lookups/s over a fixed corpus)
- size of `tables.clj`

If the generated source is too large to load fast on bb (for example over 1 s), choose a more compact encoding, such as delta-encoded strings decoded at load time. Justify the choice in the docstring. Put the measured numbers in the bead.

`bb check` must pass. Report the counts.
